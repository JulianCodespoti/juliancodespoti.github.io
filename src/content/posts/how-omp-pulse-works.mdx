[OMP Pulse](https://github.com/JulianCodespoti/omp-pulse) lets you drive terminal coding agents from your phone over Tailscale, or run the exact same daemon locally inside an unrooted Android APK when your laptop is closed.

The server is a single Rust binary (`tokio` + `axum`) with the React web client compiled straight into the executable. On a laptop or phone with thousands of past conversations, the hard part is not serving HTTP; it is keeping memory flat, history instant, and mobile data light while heavy coding-agent workers run underneath.

Here is how the pipeline works from top to bottom, with every figure backed by real measurements from our 3,365-session benchmark corpus.

## 1. Browsing in 14 MB with a lazy worker pool

The Rust daemon itself sits at roughly **14 MB** of RAM. Almost all real memory lives inside the coding-agent worker processes (`omp --mode rpc-ui`): each worker takes **281 MB** at rest, peaks near **493 MB** during startup, and needs **1.3 to 2.7 seconds** to boot.

Drawn to actual scale, one worker is **20 times larger** than the entire daemon. If opening a conversation booted a worker immediately, flipping through five chats would consume **1.4 GB** before you typed a word.

OMP Pulse separates reading from running:

- **Reading costs zero workers:** Opening a chat reads directly from disk (`14 MB` total).
- **Pre-warming on intent:** Tapping the reply box calls `POST /api/prewarm`, hiding the 2-second boot inside the time it takes you to type your prompt.
- **Capped pool with hot retargeting:** Workers share a **3-slot pool** (`891 MB` under a 12-chat burst instead of `3.4 GB`). When all 3 slots are warm, replying in a 4th chat **retargets** the oldest idle worker (`switch_session`) in **59 ms** instead of cold-booting a new process. Idle workers are reaped after 15 minutes, and any worker that grows past **700 MB** RSS is recycled cleanly between turns.

## 2. Opening a 44 MB chat in 0.59 ms

Conversations live in append-only JSONL files that can grow past **44 MB** during long debugging sessions with tool output. When you open a chat on your phone, you only need the most recent screen of messages at the bottom.

Scanning a 44 MB file from byte zero takes **36.4 ms** and pulls the entire file through memory just to return **70 KB** of recent turns. Instead, OMP Pulse seeks straight to the end of the file and reads small chunks backward until it has enough records for page 1, cutting first-screen latency to **0.59 ms** (**62x faster**).

<TailRaceFigure client:visible />

Two small caches keep the rest of the interface just as quick:

- **Parsed session cache:** Scrolling further up caches the parsed message tree by `(path, size, mtime)`, dropping repeat page loads from **105 ms cold to 17 microseconds cached**.
- **Stale-while-revalidate index:** One shared index serves all 3,365 sessions from a cached `Arc<str>` with a content-addressed `ETag`, turning steady-state polls into **0.74 ms** / **300-byte `304 Not Modified`** responses.

## 3. Streaming live tokens at one-tenth the bandwidth

While an agent writes a reply, tokens stream to your phone over a WebSocket. Sending the entire growing message on every update turns a 4,228-character turn into **244 KB** of repeated traffic (`57.8x` amplification).

Instead, each frame diffs against the previous string and sends a compact <Cue tone="sage">prefix delta</Cue>: keep `k` UTF-16 code units, append the new suffix. Measuring `k` in UTF-16 code units matches JavaScript's `String.prototype.slice` directly so emojis are never split across surrogate pairs, and suffix replacement handles trailing whitespace edits cleanly. On the same 4,228-character reply, wire traffic drops from **244 KB to 25 KB** (**9.7x smaller**).

Every delta also carries the sequence number (`base_seq`) it extends. Fast clients stay on tiny deltas; if a phone drops packets or joins mid-reply, its sequence number mismatches and the hub sends one full snapshot automatically before resuming deltas on the next token.

## 4. Keeping memory flat when your phone sleeps or loses signal

A background file watcher tails active chats and fans updates out to connected phones. Mobile connections create two constant hazards: phones drop signal in tunnels, and locked phones keep their WebSocket open in your pocket.

OMP Pulse keeps memory flat with three layers:

1. **Audience-aware sleeping:** The hub tracks only visible clients with queue headroom (`has_audience`). The moment your screen locks, the watcher parks completely instead of waking every 250 ms, queueing one refresh for when you unlock.
2. **Byte-capped queues with a stall latch:** Each client queue bounds both frame count and total bytes. Simply clearing a full queue during a **150 MB** build log immediately restores headroom so the watcher keeps reading and spikes memory by **+320 MB**. Flipping a <Cue tone="sage">stall latch</Cue> closes the intake gate until the phone reconnects and drains, keeping RSS growth at **+0 MB**.
3. **Returning memory to the OS:** Oversized watcher buffers above 256 KB are dropped once a burst settles, and on Linux glibc the maintenance loop runs `malloc_trim` so freed heap arenas return to the operating system immediately.

## 5. One writer on disk and pure-Rust push

Two final design choices keep desktop and mobile working together cleanly:

- **Single-writer routing:** Because terminal `omp` rewrites its JSONL session file from memory, two processes writing at once would overwrite each other. Before spawning a worker, the daemon checks a sidecar lock file, live process arguments, and open file descriptors. When your desktop terminal already owns the session, phone prompts route through the desktop extension instead of spawning a second writer, keeping one owner on disk while both screens stream live.
- **Zero-OpenSSL Web Push:** To notify your phone when a long run finishes without a custom cloud server or C crypto dependencies, the daemon implements RFC 8291 (`aes128gcm`) and VAPID ES256 signing in pure Rust (`p256`, `hkdf`, `sha2`, `aes-gcm`). Push relays only ever see ciphertext, and the whole binary still cross-compiles cleanly to Linux, macOS, Windows, and static `aarch64-unknown-linux-musl` for Android in about 20 seconds.
